# money — 자본주의 시뮬레이터

휴대폰 화면 기준(모바일 한 칼럼, 폭 375~430px)으로 만드는 정적 사이트예요. HTML·CSS·JS 파일만으로 돌아가고, 서버는 Firebase(Auth + Firestore)를 써요.
메시지·돈·계정이 동작하고, 나머지 화면은 자리만 있어요.

## 실행

```bash
python3 -m http.server 8000
```

브라우저에서 `http://localhost:8000`을 열어요. 휴대폰으로 보려면 같은 와이파이에서 컴퓨터 주소로 들어가요.
로그인·메시지·돈은 Firebase에 연결돼야 동작해요. 화면 구경만 하는 건 인터넷 없이도 돼요.

## 구조

```
index.html              화면 5개와 탭 바
app/app.css             화면과 탭 바 모양 (WebGL을 못 쓸 때의 CSS 대체 모양 포함)
app/app.js              화면 전환, 테마, 진단 스위치
app/icons.js            탭 아이콘 5개 (윤곽선 벡터)
app/backdrop.js         탭 바 뒤 화면을 사진으로 찍어 두는 곳 (한가할 때만, 6초 이상 간격)
app/firebase.src.js     Firebase 사용 코드 원본 (app/firebase.js는 이걸 묶은 결과물이라 직접 고치지 않아요)
app/guard.js            다른 사이트 안에 끼워 넣어 누르게 속이는 공격(클릭재킹) 막기
firestore.rules         서버 보안 규칙 (지갑·선물·이자를 서버가 직접 검사해요)
tests/                  규칙 시험 60개와 묶음 빌드 (사이트 실행에는 필요 없어요)
app/tabbar.js           탭 바: WebGL 그리기, 스프링 움직임, 터치 처리
vendor/html2canvas/     화면을 캔버스로 찍는 라이브러리 (MIT)
app/tokens.css          디자인 토큰 (Apple Store 앱 스타일)
```

## 탭 바

아이폰 26의 리퀴드 글라스 탭 바를 따라 만들었어요.

- 탭: 아래 바는 핫바가 두 쪽이에요. 첫 쪽은 메시지·돈·일·상점(카트), 바를 옆으로 휙 넘기면 둘째 쪽(랭킹·관리·무제·무제)으로 바뀌고 한 번 더 넘기면 돌아와요. 바 안의 내용만 짧고 굵게 튕기며 밀리고(지원하는 폰은 진동), 계정 버튼은 그대로예요. 천천히 끌면 예전처럼 렌즈가 따라와요.
- 누르면 선택 알약이 렌즈로 떠올라요. 다른 탭을 누르면 선택된 탭에서 눌린 탭으로 미끄러져 가고, 누른 채 끌면 손가락을 따라와요.
- 이미 선택된 탭을 다시 누르면 맨 위로 올라가요. 화면마다 스크롤 위치를 기억해요.
- 라이트/다크는 기기 설정을 따라가요.

### 어떻게 그리나요

탭 바 전체(막대 유리, 아이콘, 글자, 알약, 렌즈)를 캔버스 하나에 WebGL로 직접 그려요. 버튼은 눌림과 접근성을 위해 DOM에 그대로 있고 글자만 투명해요.

**막대 유리.** 막대와 검색 버튼이 그 자체로 유리예요. 브라우저는 "지금 이 자리 뒤에 뭐가 있는지"를 픽셀로 알려주지 않아서, 화면마다 전체 길이를 한 번 사진으로 찍어 두고(`app/backdrop.js`, html2canvas) 스크롤 위치만큼 밀어서 읽어요.
이 사진을 가운데에서 확대하고, 가장자리에서는 안쪽 내용을 끌어와 휘어 보이게 하고, 글자 같은 가는 디테일은 대비를 줄여 회색으로 비치게 해요. 안쪽 가장자리의 하이라이트와 바깥의 가는 선, 그림자도 여기서 그려요.
화면 내용이 바뀌면 0.3초쯤 뒤에 다시 찍고, 탭 바를 만지는 동안에는 미뤄요. 사진이 아직 없을 때는 CSS 유리 판(`backdrop-filter`)이 대신 보이다가 사진이 오면 0.28초 동안 서서히 넘어가요.

**알약과 렌즈.** 선택 알약과 렌즈는 같은 물체예요. `lift`가 0이면 흐린 회색 알약, 1이면 맑은 렌즈이고, 누르면 떠오르고 목표까지 8px쯤 남으면 내려앉기 시작해요. 도착할 때까지 들고 있지 않아서 탭 하나를 옮기는 데 0.4초쯤 걸려요.
렌즈는 늘 막대 유리 안에 머물러요. 끝 탭에서는 폭이 알약만큼 줄고 가운데에서는 넓어지며(위치에 따라 이어서 바뀌어요), 그림자도 막대 안에만 드리워요. 끌어도 첫 탭과 검색 버튼 밖으로는 나가지 않아요.
렌즈 가장자리에서는 뒤 화면(유리)만 휘어요. 빨강·초록·파랑이 보는 자리를 다르게 줘서 하늘색·연보라·분홍·노랑 프리즘 번짐이 생기고, 가장자리를 따라 얇은 막 같은 무지개 선이 돌아요. 글자와 아이콘은 확대만 하고 휘지 않아서 글자가 아래로 흘러내리거나 테두리 밖으로 번지지 않아요.

**이동 중 막대 전체의 프리즘.** 렌즈가 떠 있는 동안(`excite`, 0.3초에 걸쳐 켜지고 꺼져요) 막대와 검색 버튼 유리 전체가 달라져요. 하얗게 덮는 정도가 줄어 뒤 화면 색이 더 비치고, 빨강과 파랑의 확대 배율이 달라져 뒤 글자에 색 번짐이 생기고, 가장자리를 따라 무지개 선이 돌아요. 이 선의 색은 렌즈 위치를 따라 흘러요.

**움직임.** 모든 움직임은 감쇠비 1(임계 감쇠) 스프링이라 되튀거나 흔들리지 않고, 프레임마다 정확한 해석해로 풀어서 프레임 간격이 들쭉날쭉해도 떨리지 않아요. 진동수(`SPRING`)가 클수록 짧게 끝나요.

### 조절 값

`new TabBar(nav, { optics, look, glass })`로 덮어쓸 수 있고, 기본값과 설명은 `app/tabbar.js`의 생성자에 있어요.

| 이름 | 하는 일 |
| --- | --- |
| `optics` | 렌즈 굴절: 가장자리 폭, 끌어오는 거리, 감쇠, 흐림, 색 번짐, 확대 |
| `look` | 렌즈 빛: 반짝임, 둘레 빛, 무지개 선, 속 밝기 |
| `glass` | 막대 유리: 가장자리 폭, 휘는 거리, 확대, 디테일을 얼마나 남길지, 알약 흐림, 이동 중 프리즘(`film`, `exciteChroma`, `exciteKeep`, `exciteWhiten`) |

색과 테마별 값(`--tab-*`)은 `app/app.css`의 `.tabbar`에 있고, 캔버스가 읽어 가요.

### 기기에서 이상하게 보일 때

주소 끝에 붙여서 원인을 가를 수 있어요.

| 주소 | 동작 |
| --- | --- |
| `?glass=off` | 뒤 화면 사진 없이 CSS 유리 판만 써요. 사진 찍기나 굴절이 문제인지 가려요. |
| `?gl=off` | WebGL을 아예 안 쓰고 DOM 아이콘과 CSS 알약으로 보여줘요. WebGL이 문제인지 가려요. |

WebGL을 못 쓰거나 셰이더 컴파일이 실패하거나 컨텍스트를 잃어도 같은 대체 화면으로 돌아가요.

### 알려진 한계

- Chromium(SwiftShader)과 WebKitGTK에서 확인했고, 실제 아이폰 사파리에서는 아직 확인하지 못했어요.
- 막대 유리는 "찍어 둔 사진"을 보여주는 거라 화면이 바뀐 직후 잠깐은 옛 모습이 비칠 수 있어요. 영상·캔버스·iframe은 사진에 안 찍혀요.
- 앱 배경이 단색이라고 가정해요. 그라디언트나 이미지 배경이면 사진에 안 찍히고 `--background` 색으로 대신해요.
- 하얀 바탕에 내용이 적으면 유리가 티 나게 굴절할 거리가 없어서 은은하게만 보여요. 글자와 색 덩어리가 지나갈 때 뚜렷해져요.

## 화면

- 스타일은 실제 Apple Store 앱(iOS 26) 화면을 따라요. 연한 회색 바탕, 모서리 28px의 큼직한 흰 카드, 굵은 큰 제목(스크롤하면 접히면서 위쪽 유리 바와 작은 제목이 나타나요), 위쪽 유리 버튼, 가로로 넘기는 카드 줄이에요. 사진 자리는 색이 번지는 면으로 대신했어요.
- 메시지: iOS 26 메시지 앱처럼 흰 바탕에 위쪽 고정 대화(동그라미), 납작한 목록, 검색, 읽지 않음 필터, 편집이 있어요. 대화·고정 동그라미·말풍선을 꾹 누르면 메뉴가 나와요(고정, 읽음 표시, 삭제, 복사). 대화 배경은 처음에 흰색이고 이름 알약을 눌러 노을·오로라·밤하늘·민트로 바꿀 수 있어요. 받은 말풍선은 회색 유리예요(예시 데이터예요).
- 계정: 기본 프로필, 게시물 0개 빈 상태, 프로필 편집(이름·소개는 이 기기에만 저장돼요). 이름을 바꾸면 기본 사람 모양 대신 첫 글자가 보여요.
- 로그인: 계정 탭에서 아이디와 비밀번호로 가입·로그인해요(안 보이는 가짜 이메일로 파이어베이스 이메일 로그인에 연결). 처음 쓰던 익명 계정에 이어붙어서 그동안의 대화와 프로필이 그대로 남아요. 비밀번호를 잊으면 되찾을 수 없어요.
- 문구는 해요체로 써요.

- 화면 모양은 첨부해 주신 Apple Store 앱 스크린샷과 UI 명세를 따랐어요.
- 톱니바퀴 아이콘은 첨부해 주신 이미지를 벡터로 따서 만들었고, 종이비행기도 첨부해 주신 윤곽선 이미지를 따랐어요.

## 파이어베이스 연결

익명 로그인으로 프로필, 대화 배경화면, 대화(고정·알림·메시지)를 Firestore의 `users/{내 uid}` 문서에 저장하고 다시 열면 불러와요. 설정값이 비어 있으면 이 기기에만 저장해요.

1. [콘솔](https://console.firebase.google.com)에서 프로젝트를 만들고, 프로젝트 설정 → 내 앱에 웹 앱(`</>`)을 추가해요.
2. 나온 `firebaseConfig` 값을 `app/firebase-config.js`에 붙여 넣어요.
3. Authentication → 로그인 방법에서 **익명**을 켜요.
4. Firestore Database를 만들고(프로덕션 모드), 규칙에 `firestore.rules` 내용을 붙여 게시해요.
5. Authentication → 설정 → 승인된 도메인에 `devtoolxd.github.io`를 추가해요.

## 보안과 서버 사용량

**규칙이 서버에서 지켜요.** 앱 코드는 누구나 고칠 수 있어서, 토큰(지갑)·선물·이자·메시지 규칙은 모두 `firestore.rules`가 검사해요.
남의 지갑 읽기·쓰기, 잔액 늘리기, 선물 두 번 받기, 보낸 사람 위조, 너무 큰 사진·글, 너무 빠른 연속 쓰기가 전부 막혀요. 이자는 상품 가격표와 초당 이자율을 규칙이 알고 있어서 부풀린 값은 거절돼요.

```bash
cd tests && npm install
npm run rules   # 에뮬레이터로 공격 시나리오 60개 시험
npm run build   # app/firebase.src.js를 고쳤다면 app/firebase.js를 다시 만들어요
```

- 익명 로그인은 쓰지 않아요. 아이디·비밀번호(내부적으로 `아이디@money-sim.app`) 로그인만 되고, 콘솔에서 이메일/비밀번호 로그인이 켜져 있어야 해요.
- Firebase SDK를 직접 묶어 이 저장소에서 내려주기 때문에 CSP를 `script-src 'self'`로 좁혔어요. 사진은 `data:image/jpeg|png`만 허용하고, 사용자가 넣은 글은 모두 이스케이프해요.
- 규칙은 `toss-style-site`에 `firestore.rules`가 올라오면 GitHub Actions가 자동 게시해요.

**랭킹.** `ranks/{uid}` 문서에 내 잔액을 올리면 모두가 볼 수 있는 순위표가 돼요. 규칙이 내 지갑 잔액·내 프로필 이름과 똑같은 값만 받고 20초에 한 번만 갱신해서, 값을 부풀려 올릴 수 없어요. 순위는 상위 50명만 읽고(45초 캐시), 내 순위는 나보다 많이 가진 사람 수(최대 50)로 세요. 이번 주·이번 달 순위는 아직 없어요.

**서버·CPU 아끼기.** 메시지는 최근 40개만 실시간으로 듣고 옛 글은 올려볼 때만 불러와요. 프로필은 30분 캐시, 이자는 10분마다 한 번만 정산하고 그사이엔 화면에서 계산해요. 지갑 쓰기는 2.2초 이상 간격으로 줄을 세워요.
화면 사진 찍기(html2canvas)는 한가할 때만, 화면 내용이 실제로 바뀌었을 때만 해요. 돈 탭을 20초 가만히 둘 때 사진 찍기가 15번에서 0번으로, CPU 시간이 17.7초에서 0.29초로 줄었어요 (Chromium 측정).

### 알려진 한계

- 새 계정은 0 토큰으로 시작해요. 그래도 계정을 여러 개 만들어 선물로 토큰을 모으는 방법은 막지 못해요 (이메일·전화 인증, App Check 없음).
- 비밀번호 규칙은 앱에서만 검사해요. Firebase 콘솔의 비밀번호 정책은 따로 설정해야 해요.
- 실제 아이폰과 실제 서버에서는 아직 확인하지 못했어요. 규칙 시험 60개와 가짜 서버 화면 시험만 통과했어요.

## 탭 구성과 상태

- 핫바 첫 쪽: 메시지·돈·일·상점, 둘째 쪽: 랭킹·인벤토리·사업·무제. 관리는 탭이 아니라, 아이디가 `owner`인 사람에게만 계정 탭 위쪽(편집 왼쪽)에 보이는 버튼으로 열어요. 이 숨김은 화면에서만 하는 거라, 관리 기능이 생기면 서버 규칙에서도 owner만 허용해야 해요.
- 상태(배고픔·목마름·에너지)는 어느 탭에서나 떠 있는 동그란 i 버튼으로 열어요. 누르면 돌면서 세 개가 튀어나오고, 끌어서 옮기면 놓은 자리에 그대로 있어요. 값(72·41·89%)은 아직 고정된 자리표시 값이에요.
- 이자 상품 가격은 1 토큰 = 1 달러쯤으로 맞춰 20~1,262 토큰이에요 (`firestore.rules`의 가격표와 `app/app.js`의 `PRICE`가 같아야 해요).

## 사업과 상태 (기초)

- **상품 그림:** `app/shapes.js`의 도형이에요. 페트병 10종×5크기(330ml~2L), 뚜껑 10종, 과자·젤리·빵 봉지, 도시락 용기, 고기 10종(트레이 위), 에너지 캔, 커피 컵, 에너지바 포장을 검은 윤곽선으로 그려요. 같은 번호는 늘 같은 모양이에요. 그림을 고치면 `firestore.rules`의 번호 범위(0~49)와 맞는지 확인해요.

- **창업과 회사 여러 개:** 사업 탭에서 "회사 더 만들기"(또는 처음의 "10 토큰으로 창업하기")를 누르면 회사 이름·마크(사진, 선택)·업종(식품·컴퓨터·인공지능)을 정해 회사를 만들어요. 회사를 여러 개 만들 수 있고, 한 번 만들 때마다 10 토큰이 빠져요. 회사는 `companies/{자동 번호}` 문서로 만들고, `owner` 칸에 사장의 아이디를 적어요. 고른 회사 이름을 누르면 그 회사의 팔 상품·직원 채용·업종을 봐요. 업종은 사장이 회사 프로필(사업 탭 오른쪽 위 회사 마크)에서 바꿔요. 회사 문서와 10 토큰이 빠지는 지갑 쓰기가 한 묶음일 때만 받아요. 예전에 만든 회사는 문서 번호가 사장의 아이디예요.
- **돈 탭:** "이번 달 쓴 토큰"과 "내 카드" 칸은 지웠어요.
- **팔 상품 정하기:** 전체 화면으로 열려요. 첫 화면은 식품·컴퓨터·인공지능 세 개의 둥근 사각형이에요. 회색 리퀴드 글라스(돈 보내기 시트와 같은 재질)에 검은 윤곽선 아이콘을 얹었어요. 식품은 물, 음식(간식·식사), 에너지 식품으로 나뉘고, 물은 페트병 모양(50) → 뚜껑 모양(50) → 뚜껑 색(50), 젤리·과자·빵·도시락·고기는 용기 모양(50) → 색(50), 에너지바·에너지 음료·커피는 용기 모양(50) → 내용물(6) → 색(50)으로 골라요. 칸에서 하나를 고르면 미리 보여주고, 확인을 눌러야 다음으로 넘어가요. 마지막에 이름과 가격을 정해요. 컴퓨터와 인공지능은 자리만 있어요. 그림은 `app/biz.js`의 도형(SVG)이고, 가운데에 회사 로고가 들어가요. 인공지능 아이콘은 머리와 휜 살 10개, 식품 아이콘은 잎 세 장과 사과가 든 그릇을 윤곽선으로 간단히 옮긴 그림이에요.
- **원가와 가격:** 원가는 센트 정수로 계산하고 화면에는 토큰으로 보여줘요 (50센트 = 0.5 토큰, 1 토큰 = 1달러). 값의 근거: 생수 페트병(8~20센트)·뚜껑(1~5센트)·라벨(2~10센트)은 ThePricer 검색값, 음료 캔은 250ml 캔 1,000개 €1,090을 한 개로 환산한 약 11센트(추정), 커피 컵은 12온스 컵·뚜껑·슬리브 세트 22~37센트(Walmart 100개 $21.99, Quill 500개 $186.99), 도시락 용기는 UCHANGE 17온스 크라프트 박스 92센트와 Global Sources 플라스틱 용기 30~62센트, 고기는 2026년 6월 축산물 가격표 1kg 21,000~25,000원을 1달러 = 1,400원으로 바꿔 150g에 약 2.14달러. 봉지 필름, 내용물, 에너지바 포장은 찾지 못해서 추정이에요. 가격은 직접 정하고, 추천 가격은 원가의 2배예요. 팔기를 누르면 `companies/{uid}/products/{id}` 문서가 생기고, 규칙이 종류·모양·색·이름·원가·가격(센트 정수)을 검사해요.
- **판매 목록과 관리:** 상품마다 ⋯ 버튼이 있어요. 이름 바꾸기, 판매 멈추기(판매 다시 시작하기), 판매 종료하기 중에서 고를 수 있어요. 멈추기와 종료는 "정말 하시겠습니까?"로 한 번 더 물어봐요. 규칙은 이름·멈춤(paused)·종료(active를 false로)만 허락하고, 끝낸 상품은 더 바꿀 수 없어요. 예전 토큰 단위(cost·price) 상품은 목록에서 센트로 바꿔 보여줘요. 아직 판매가 수익으로 이어지지는 않아요.
- **직원 채용 (사업 탭):** 판매 중인 상품 아래에서 + − 로 정한 숫자가 곧 모집 인원이에요. "모집 인원 N명으로 맞추기"를 누르면 그 숫자로 맞춰져요 (늘리거나 줄이거나, 숫자에는 제한이 없어요). 인공지능 직원은 아직 막아 두었어요.
- **회사 종류:** 창업할 때 식품·컴퓨터·인공지능·원자력 발전 가운데 하나를 골라요. 업종은 사업 탭 오른쪽 위의 회사 마크를 눌러 열리는 회사 프로필에서 바꿔요. 예전에 만든 회사는 식품 회사로 봐요.
- **일 탭:** 사장이거나 직원이면 회사 일을 해요. 직원은 성능을 올려요. 식품 회사 직원은 배합을 다듬어 식품 성능을 올리고, 사장은 식품 공장을 돌려요. 사장이 만들 개수를 정해 생산을 시작하면 공장이 1초에 공장 등급만큼 만들고(1초에 1 토큰), 다 만들면 받아서 재고에 넣어요. 한 번에 정할 수 있는 양은 식품 성능까지예요. 공장 등급은 금고에서 등급 × 10 토큰을 내고 올려요. 만든 음식은 상점에 진열돼요. 원자력 발전·컴퓨터·인공지능 회사는 아래 연구실 일을 해요. 월급은 아직 없어요.
- **상점 탭:** 재고가 있는 음식을 여러 회사에서 모아 보여줘요 (최대 50개, 회사 이름과 그림). 개수를 고르고 사면, 내 지갑에서 값이 빠지고(센트는 올려서 토큰으로), 파는 회사 금고로 그만큼 들어가고, 재고가 그만큼 줄어요. 세 가지는 같은 묶음에서 바뀌어요 (`firestore.rules`의 상점 규칙). 음식을 먹는 것은 아직 없어요.
- **꺼내기 (사장만):** 사업 탭에서 재고가 있는 음식의 `꺼내기`를 누르면 창고에서 한 개가 줄고, 내 인벤토리에 한 개가 들어가요. 두 기록은 같은 묶음에서 바뀌고 규칙이 확인해요.
- **인벤토리 탭:** 상점에서 산 음식과 꺼낸 음식이 들어가요. 음식을 누르면 `먹기` 버튼이 나오고, 먹으면 한 개가 줄고 상태가 올라가요. 물은 목마름 +40, 간식은 배고픔 +20, 식사는 배고픔 +40, 에너지 식품은 에너지 +40이에요. 100을 넘지 않아요.
- **연구실 (원자력 발전·컴퓨터·인공지능):** 배합·검사·데이터 받기는 일 탭에서, 발전·출시는 사업 탭의 연구실 카드에서 해요. 숫자는 사장과 직원이 함께 쌓고, 눌러 쌓은 숫자는 2.5초 뒤에 한꺼번에 서버에 저장해요. 저장된 숫자는 줄지 않아요.
  - 원자력 발전: 핵연료는 처음부터 있어요. 배합은 일 탭에서 해요. 재료 3가지(분말·안정제·촉매)를 골라 스포이드로 한 방울씩 떨어뜨려 목표 색에 맞추고, 꾹 눌러 섞어요. 8방울까지 넣을 수 있고, 목표 색에 가까울수록 핵연료 성능이 1~30 사이에서 더 많이 올라가요. 발전은 사업 탭에서 해요. 만들 전기 양을 적으면 걸리는 시간과 비용이 정해지고, 둘은 같아요 (1초 = 1 토큰, 회사 금고에서 나가요). 성능이 높을수록 적은 돈으로, 빨리, 한 번에 많이(최대 성능 × 10) 만들어요. 다 되면 창고에 받아요.
  - 컴퓨터: 부품 검사판에서 열이나 스파크가 뜬 곳을 누르면 처리 용량·처리 속도·전기값 가운데 하나가 1~8 랜덤으로 올라가요. 출시하면 그때의 세 숫자가 저장돼요.
  - 인공지능: 가짜 검색에서 받기를 누르면 데이터가 20~400 MB 랜덤으로 쌓여요. 컴퓨터를 사 두면 사장이 데이터를 학습시킬 수 있어요. 배치 수는 올림(데이터 ÷ 처리 용량), 전기는 배치 수 × 전기값, 걸리는 시간은 올림(배치 수 ÷ 처리 속도), 개발 점수는 데이터 × (용량 + 속도) ÷ 100(내림)이에요. 전기는 학습을 시작할 때 창고에서 나가고, 결과는 시간이 지나면 받아요. 출시하면 개발 점수가 출시 점수가 돼요. 사용 시간 단가(1시간)는 사장이 정해요.
  - 인공지능 사용: 다른 회사가 출시한 인공지능의 사용 시간을 시간당 단가로 살 수 있어요. 사용의 효과(작업 속도·효율에 주는 영향)와 인공지능 직원 뽑기는 아직 없어요.
- **취업:** 회사도 없고 다니는 곳도 없으면 회사를 종류별로 보고, 이름으로 찾고, 인기순·시총순·남은 자리 적은 순·남은 자리 많은 순·최근 창업순으로 골라 지원해요. 목록은 최근에 만든 50곳을 읽고, 이름 찾기는 20곳까지 읽어요.
- **시가총액:** 아직 매출이 없어서 임시로 창업 자본 10 토큰 + 직원 1명당 2 토큰으로 계산해요. 매출이 생기면 여기에 더할 거예요.
- **일자리 규칙:** 사장은 자기 회사의 모집 인원을 늘리고 업종을 바꿀 수 있어요. 입사·퇴사는 일자리 기록(jobs)과 회사의 모집·직원 수가 같은 묶음에서 함께 바뀔 때만 받아요. 내 회사에는 지원할 수 없지만, 사장도 다른 회사에 다닐 수 있어요. 일자리 기록은 본인만 읽어요.
- **상태:** 배고픔은 24시간, 목마름은 18시간, 에너지는 36시간에 100%가 다 닳아요 (`STATS`와 규칙의 쓰러짐 검사가 같아야 해요). 20% 이하면 화면 가장자리가 붉어지고, 10% 이하면 일렁이고, 5% 이하면 심장 박동처럼 깜빡여요. 0%가 되면 서버에 기록되고(닳지 않았는데 기록하려 하면 규칙이 거절해요) 모든 상태가 10%로 돌아오며, n번째 쓰러지면 n시간 동안 쉬어요.
- **아직 없는 것:** 상태를 채우는 방법은 지금은 인벤토리에서 먹기뿐이에요. 쉬는 시간은 화면에서만 막아요 (서버는 기록만 지켜요).
